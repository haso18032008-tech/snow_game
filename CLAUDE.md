# CLAUDE.md

Снежная ферма — браузерная игра (Three.js, без сборщика) + небольшой Django-бэкенд для аккаунтов,
облачного сохранения и таблицы лидеров. Бывшая часть Финстата, теперь самостоятельный проект.
Деплой на Render.

## Команды

- Запуск локально: `python manage.py runserver` (SQLite, переменные окружения не нужны)
- Проверка перед сдачей: `python manage.py check`, затем функциональная проверка через
  `python manage.py shell` с `django.test.Client` — отдельного набора тестов нет
- После изменения моделей: `makemigrations` + `migrate`
- `DATABASE_URL` переключает SQLite → PostgreSQL. База у игры СВОЯ, не база Финстата

## Структура

- `config/` — настройки (один файл на локаль и прод, прод включается переменными окружения)
- `snow_game/` — единственное приложение: модель `GameSave`, API (`/api/save/`, `/api/leaderboard/`),
  админка, команды `ensure_admin` и `import_players`
- `snow_game/static/snow_game/js/` — клиент игры; порядок подключения скриптов важен (см. `index.html`)
- `templates/allauth/layouts/base.html` — единственный наш шаблон входа/регистрации, остальное из allauth

## Конвенции

- Комментарии в коде — на русском, объясняют «почему так», а не «что делает строка»
- Аккаунты — только через allauth (логин/пароль + Google). Своих форм регистрации не писать
- Всё серверное привязано к `request.user`; чужое сохранение достать нельзя
- Клиент присылает состояние — на сервере оно только чистится в `clean_state()`, ему не доверяют
- Игра должна работать без входа и без сети (localStorage); сервер — дополнение, а не условие

## Известные грабли

- `cloud.js` сверяет `uid` с меткой владельца в localStorage — поэтому при переносе игроков
  сохраняются исходные id (`import_players`)
- Админ не удаляет сохранения (это ломает `reset_epoch`), только сбрасывает их действием
- Render (бесплатный тариф) — нет Shell: команды запускать через `build.sh` или локально с внешним `DATABASE_URL`
- `legacy_import.js` — временный (разовый перенос прогресса со старого домена), потом удалить вместе с `<script>` в `index.html`

## Джунгли, дробовик, Грустити, железная дорога (ноябрь 2026)
- **Север (z < `SG.JUNGLE.z`=-118)** — джунгли за стеной тропических гигантов (топор «ур. 28», `SG.JUNGLE_NEED_LVL`). Гиганты стены и внутри
  идут в `G.giants` ПОСЛЕ восточных (`G.jgStart`), с флагом `jg`; индексы восточных не менялись, `S.cut` остаётся верным.
- **Пальмы** (`G.palms`, 450 шт.): рубятся топором, дают обычное дерево; ~6% «банановые» (дают бананы, отрастая, могут стать банановыми).
- **Мобы джунглей** — в `G.bears`, kinds 5 (обезьяна), 6 (горилла-босс), 7 («Любопытстити», сам подходит, после удара убегает). Падают бананы.
  `confine()` держит мобов в своих зонах; поляна базы (`inJClearing`) для мобов закрыта.
- **Джунгли-база** (`jbase`): лавки `jwood` (res `wood`) и `banana` (`SG.JSTALLS`, товар из `S[st.res||st.id]`), свой поток покупателей (`flow: 'jungle'`).
- **Дробовик** (`gun`, `gdmg`, `grate`, `gcount`): кружит по внутреннему кольцу, сам стреляет по ближайшему мобу (`updateGuns`), работает одновременно с топором.
- **«Грустити»** — `G.sad` (не в `G.bears`): ныряет/всплывает, бьётся только гарпуном, награда — рыба.
- **Железная дорога**: `rail` (3 уровня: дрезина/поезд/метро) на основной базе, `railf` (после пирса на макс.), `railj`. Станции — `G.stations`,
  поездка `G.startRide`. Станция стоит РЯДОМ с плиткой (`SG.RAIL.*`: `tile` — плитка покупки, `x/z` — станция, `land` — куда выходишь).
  Выбор направления — в `ui.js` (`UI.railBegin/railTick/railRelease`): отпустить джойстик → нажать → вести в область (подсвечивается);
  поехать — только когда отпустил джойстик на подсвеченной области; отпустил в центре или «Отмена» — остался.
- **Охотники с мачете** (`jhire` — число, `jhdmg` — урон; `G.hunters`, `updateHunters`): бегают за обезьянами, бананы с убитых сразу идут на банановую лавку.
- **Магнит на корабле**: пока игрок на борту, дальность = `D.magnet + shipSpeed*0.6`, скорость притяжения = `max(16, shipSpeed*2.4)` (`updateDrops`).
- Пальмы низкие (≈3.5 м, `makePalmGeo` в `render.js`), чтобы не закрывать поле.
- **Стрелка у ног героя** показывает на базу того биома, где он стоит (`G.biomeAt`): основная — жёлтая, море — голубая, джунгли — оранжевая
  (`SG.BASES`, `SG.ARROW_COLORS`). **Возрождение** — на базе биома смерти (`p.deadIn`, `SG.RESPAWN`), если база там уже построена, иначе на основной.
- **База в джунглях растёт** (`jup`, ур. 0..4): бамбуковая ограда (`SG.jbRect(L)`, рисует `buildJFence`), лечение внутри (+3+L HP/с), цены джунглевых
  лавок +20%/ур., покупатели чаще +25%/ур., лимит охотников 2+2·L. Мобы в зону базы (по ур. 4, `inJClearing`) не заходят. Ограда — только внешний вид, игрока не держит.
- **Мир расширен на север**: `SG.JUNGLE.zMin = -300` (джунгли глубиной ~180 м; игрок/мобы/пальмы/гиганты до zMin). Новые гиганты (продолжение восточной
  стены и одиночные в новой полосе) добавлены в самый конец `G.giants`, чтобы индексы `S.cut` не сдвинулись. Пальм 1100, обезьян 32, горилл 6.
- Новые ключи сохранения: `banana`, `stall.jwood`, `stall.banana`, stats `monk curio grust palms banana soldjwood soldbanana rides hmonk`
  (сервер `clean_state` обновлён). Все числа баланса — в `config.js` (`SG.F.g*`, `SG.U`, `SG.RAIL`, `KINDS` в `game.js`).
